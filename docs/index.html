Task

One intent, many SQL dialects

Most text-to-SQL benchmarks evaluate SQLite only. UniQL keeps questions, schemas, and database contents aligned while expanding each example to ClickHouse, Doris, Drill, Druid, DuckDB, Hive, MySQL, Oracle, PostgreSQL, Presto, Spark, SQLite, StarRocks, Teradata, Trino, and T-SQL.

Models receive the target dialect, schema, natural-language question, and optional evidence. They must output one executable SQL query for the requested engine.

Metric

We report execution accuracy. Predicted and reference SQL are executed on the same target database and compared under the UniQL protocol, preserving order when semantically required and duplicate multiplicities for unordered outputs.

Submit

Leaderboard submission package

  1. Run inference for each dialect using the UniQL prompt and data files.
  2. Run evaluation/evaluate.py to produce one evaluation-result JSON per dialect.
  3. Package your files in a zip with metadata.json and the result JSON files.
  4. Open a GitHub issue using the leaderboard submission template and attach or link the package.

The maintainers recompute aggregate, difficulty, and construction-source metrics from the submitted JSON files before updating the leaderboard.

Tracks

UniQL-1534: full 1,534-question benchmark.

UniQL-Hard-256: hard subset using data/subsets/hard_256/question_ids.txt.

Format

Evaluation-result JSON

Submit the JSON files produced by evaluation/evaluate.py. Each file is a JSON array. The required fields for leaderboard aggregation are sql_idx or question_id, and res. We recommend preserving the full evaluator output for auditability. 

[
  {
    "sql_idx": 0,
    "res": true,
    "timeout": false,
    "error": null,
    "predicted_sql": "SELECT ...",
    "ground_truth_sql": "SELECT ...",
    "db_path": ".../california_schools.sqlite",
    "dialect": "mysql"
  }
]
